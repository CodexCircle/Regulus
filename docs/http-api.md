# HTTP API

`GET /api/agents` returns the connected agents as JSON (id, version, system info, `status` of `connected` or `stale`, last heartbeat, uptime). `GET /api/agents/{id}/metrics` returns the recent metrics of an agent (CPU, load, memory, swap, disks, network counters and rates, uptime), oldest first; `?since=<RFC 3339>` returns only newer points. The hub keeps the last hour of metrics in memory (up to 3600 reports per agent), so the history is lost when the hub restarts. Network rates are computed from the times the agent took the two reports (`collected_at`), not from when the hub received them, so a delayed or bunched delivery does not make a spike; a rate is left out (`null`) when the two reports are the same instant, out of order, or more than 5 minutes apart, and reports without `collected_at` (older agents) fall back to the receive times. `GET /api/agents/{id}` returns one agent. `GET /api/agents?all=true` also lists the enrolled agents that are `offline` or `revoked`, with the time the hub last heard from them (`last_seen_at`); `PATCH /api/agents/{id}` (`servers.manage`) gives an agent a display name. `GET /api/layout` and `PUT /api/layout` read and save the dashboard layout of the logged-in user (any JSON up to 64 KiB, stored per user). `GET /api/stream` upgrades to a **WebSocket** that pushes a `snapshot` of the agents and then `agent.connected`, `agent.disconnected`, `agent.heartbeat` and `agent.metrics` events as JSON; it needs the session cookie (rechecked every 30 seconds: the stream closes when the session ends or the user loses `servers.read`) and refuses pages from other origins, and a client that reads too slowly is disconnected and should reconnect. All of this is described in [`internal/hub/openapi.yaml`](../internal/hub/openapi.yaml), also served at `/api/openapi.yaml`; a test keeps the file in sync with the routes. The endpoints need a login and `GET`s are read-only; the dashboard shows the servers on the **Servers** page.
